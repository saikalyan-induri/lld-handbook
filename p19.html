A. Realistic Interview Prompt

"Design an e-commerce shopping cart and checkout system. Users add products to a cart, optionally add per-item add-ons like gift wrap, apply coupons, and check out. Checkout must handle tax, discounts, and inventory correctly under concurrent load."

B. Difficulty

Intermediate, climbing to Advanced on the checkout-concurrency and pricing-pipeline follow-ups. The cart itself is simple; the interesting design decisions are (1) picking Decorator for stackable per-item add-ons instead of misusing Strategy for them, and (2) making inventory decrement race-free under concurrent checkouts.

C. What This Problem Tests

  • Decorator for per-item add-ons (gift wrap, extended warranty, engraving) that stack and each contribute their own price/behavior — deliberately distinguished from Strategy
  • Strategy for the pricing pipeline (tax, discount, coupon) — a fixed, ordered sequence of interchangeable rules applied to a running total
  • State machine for order lifecycle (placed → paid → shipped → delivered, plus cancelled/refunded)
  • The check-then-act race on inventory decrement under concurrent checkouts of the same product
  • Idempotent payment webhook handling, the same lesson already established for Movie Ticket Booking (Problem 17)

D. Requirements

Functional

  1. Add/remove products from a cart, with optional per-item add-ons
  2. Apply a coupon code and compute tax and discounts at checkout
  3. Check out, decrementing inventory and creating an immutable order
  4. Track order status from placed through delivered, including cancellation/refund

Non-Functional

  • Concurrent checkouts for the last unit of a product must not oversell it
  • A retried payment confirmation webhook must not double-charge or double-create an order
  • Adding a new discount rule or a new add-on type must not require touching the cart or checkout core logic

I. Class Relationships

  • Decorator for add-ons, Strategy for the pricing pipeline — and why they're not the same tool: this is the canonical place in this document to make that boundary explicit. An add-on (gift wrap, engraving) wraps a specific cart item and stacks arbitrarily — an item can have gift wrap and engraving and extended warranty all at once, each layering its own price on top of the last, which is exactly Decorator's shape. A pricing step (tax, a specific discount rule, a coupon) is not attached to one item and does not stack arbitrarily — it's one selected algorithm applied once, in a fixed pipeline position, to a running total, which is Strategy's shape. Reaching for Strategy to model add-ons (one "AddOnStrategy" enum picking exactly one add-on) would break the moment two add-ons need to combine on the same item; reaching for Decorator to model tax/discount (wrapping the cart in a "TaxDecorator") would obscure that these are pipeline stages applied in a specific, meaningful order, not arbitrarily stackable wrappers.
  • Cart vs. Order is the mutable-draft-vs.-frozen-snapshot split, once more: Cart is mutable right up until checkout; Order is an immutable record of exactly what was charged, at what price, with what add-ons — the same "shared template vs. frozen instance" family as Book/BookItem, Room/RoomInventory, Seat/ShowSeat, and Food Delivery's OrderLineItem (Problem 18), now applied to an entire cart's worth of line items at once, including their decorator-priced add-ons.
  • State machine for order lifecycle: the same shape as Food Delivery's OrderState (Problem 18), tailored here to a payment-gated first transition and a cancellation/refund path that food delivery didn't need to model.

O. Design Evolution

  • V1: a cart with no add-ons, one flat price, no tax/discount, synchronous checkout, no order lifecycle tracking.
  • V2: introduce CartItemDecorator the moment a second add-on type is requested — this is exactly when a single "addOnType" field would need to become a set, signaling the shift to a stackable Decorator chain.
  • V3: extract the PricingStep pipeline once tax and discounts both need to apply, in order.
  • V4: formalize OrderState once cancellation/refund and asynchronous payment confirmation are requested.
  • V5: add the idempotency key on checkout confirmation once payment moves from synchronous to webhook-based.

What stays stable: CheckoutService's public checkout/confirm API. New add-ons and pricing stages are additive.

Order checkout(Cart cart, String couponCode) {
  List<String> orderedProductIds = sort(cart.getItems().stream().map(i -> i.getProduct().getId()).collect(toList()));   // canonical order, avoids cross-cart deadlock
  List<String> reserved = new ArrayList<>();
  try {
    for (String productId : orderedProductIds) {
      lock(productId);
      Product product = productFor(productId);
      int qty = cart.quantityFor(productId);
      if (product.getStock() < qty) { rollback(reserved); throw new OutOfStockException("out of stock"); }
      product.setStock(product.getStock() - qty);
      reserved.add(productId);
    }
    Money total = cart.subtotal();   // includes decorator-priced add-ons
    for (PricingStep step : pricingPipeline) { total = step.apply(total, cart); }
    Order order = new Order(freeze(cart.getItems()), total, /* status = */ PENDING_PAYMENT);
    return order;
  } finally {
    for (String productId : reserved) { unlock(productId); }
  }
}

U. Testing Strategy

  • Happy path: an item with two stacked add-ons prices as base + add-on A + add-on B, and the pipeline applies tax/discount/coupon in the documented order.
  • Edge cases: checking out a cart where one line item is out of stock rolls back all reservations made earlier in that same checkout, not just the failed one.
  • Idempotency tests: calling confirmPayment() twice with the same idempotency key produces exactly one PAID transition and one charge.
  • Concurrency tests: two customers concurrently checking out the last unit of the same product result in exactly one success and one clean "out of stock" rejection.

W. Concurrency

Shared mutable state: each Product's stock count, particularly for a popular item near its last few units.

  • The check-then-act race, on inventory this time: reading "is there enough stock" and then decrementing it are two steps; without a lock (or an atomic conditional update) around the specific product, two concurrent checkouts could both read sufficient stock before either commits — the same bug shape as Parking Lot, Splitwise, ATM, Library, Hotel, and Movie Ticket Booking, now on inventory rows.
  • Multi-item checkout deadlock avoidance: a checkout touching several products must lock them in a fixed canonical order (sorted by product id) to avoid the same circular-wait deadlock already solved in File System (Problem 9) and Movie Ticket Booking (Problem 17).
  • Database-level alternative: a single atomic UPDATE products SET stock = stock - qty WHERE id = ? AND stock >= qty avoids application-level locking entirely for the single-product case — the affected-row-count tells the caller whether the decrement succeeded, pushing the race-free guarantee down to the database.
  • Idempotent payment confirmation: exactly the same idempotency-key discipline as Movie Ticket Booking (Problem 17) — a retried webhook must return the already-processed result, not reprocess it.

X. Persistence

Orders and their frozen line items (including decorator-priced add-ons) are durable, legally significant records. Cart contents are more ephemeral — losing an unfinished cart on a crash is a UX annoyance, not a correctness failure — so a cart can reasonably live in a faster, less durable store than the order it eventually produces.

Z. Failure Scenarios

  • Inventory is decremented but the order creation step fails afterward: the decrement and order creation must be transactionally consistent, or the decrement needs a compensating restore — the same commit-ordering discipline as ATM's (Problem 14) debit-before-dispense logic.
  • A payment fails after inventory was already reserved: confirmPayment()'s failure path must restore the reserved stock, not leave it permanently decremented for an order that was never actually paid for.

AA. Common Bad Designs

  • Using Strategy to model add-ons, or Decorator to model the pricing pipeline — the defining pattern-boundary mistake for this problem; see I.
  • Checking stock and decrementing it as two separate, unlocked steps — reopens the classic check-then-act race even with a well-designed Product entity.
  • Locking multiple products in whatever order they appear in the cart instead of a canonical sorted order — the same deadlock trap as unordered multi-seat/multi-file locking.
  • Treating payment confirmation as safe to process more than once — without an idempotency key, a retried webhook can double-create an order or double-charge.

AC. Interviewer Evaluation

Strong signal: correctly choosing Decorator for add-ons and Strategy for the pricing pipeline, and being able to articulate why swapping them would break; independently identifying the inventory check-then-act race and the multi-item deadlock risk; flagging payment-confirmation idempotency without being prompted.

Red flag: modeling add-ons as a Strategy enum that can't stack; modeling the pricing pipeline as nested Decorators; unlocked stock check-then-decrement; unordered multi-item locking; non-idempotent payment confirmation.

AD. Interview Simulation

Interviewer: Design an e-commerce shopping cart and checkout flow. Items can have add-ons like gift wrap.
Candidate: I'd model add-ons with Decorator, not Strategy — because add-ons stack. A watch can have gift wrap and engraving at once, each layering its own price contribution on top of the base item. Strategy would only fit if exactly one add-on could ever apply, which isn't the real requirement here.
Interviewer: How do tax and discounts fit in, then?
Candidate: Those are Strategy, not Decorator — each is one rule applied once, at a specific, meaningful position in an ordered pricing pipeline. Tax-before-or-after-discount is an actual business rule, so I'd make the pipeline an explicit ordered list of PricingSteps rather than implying an order through nested wrapping.
Interviewer: Two customers check out the last unit of a product at the same time.
Candidate: Same check-then-act race as everywhere else in this document — lock the product, re-verify stock, then decrement. In production I'd actually push this to an atomic conditional update at the database level, so the race-free guarantee doesn't depend on application-level locking at all.
Interviewer: What if the payment provider retries its confirmation webhook?
Candidate: Idempotency-keyed confirmation, same as I'd do for the movie-ticket payment flow — a retried call with the same key returns the already-processed order instead of creating a second one or charging twice.

// Problem 19: E-commerce Shopping Cart & Checkout
// Patterns: Decorator (add-ons on CartItem), Strategy (pricing pipeline), State (Order lifecycle), Facade (CheckoutService)
import java.util.*;

public class p19 {

    // ---------- Exceptions ----------
    static class OutOfStockException extends RuntimeException {
        OutOfStockException(String msg) { super(msg); }
    }
    static class OrderNotFoundException extends RuntimeException {
        OrderNotFoundException(String msg) { super(msg); }
    }

    // ---------- Catalog ----------
    static class Product {
        final String id;
        final String name;
        final double price;
        int stock;

        Product(String id, String name, double price, int stock) {
            this.id = id; this.name = name; this.price = price; this.stock = stock;
        }

        void decrementStock(int qty) {
            if (stock < qty) throw new OutOfStockException("Insufficient stock for " + id);
            stock -= qty;
        }

        void restoreStock(int qty) { stock += qty; }
    }

    // ---------- CartItem (component) + Decorator ----------
    static class CartItem {
        final Product product;
        final int quantity;

        CartItem(Product product, int quantity) {
            this.product = product; this.quantity = quantity;
        }

        double getPrice() { return product.price * quantity; }
        Product getProduct() { return product; }
        int getQuantity() { return quantity; }
    }

    // Abstract decorator: subclasses CartItem so it's substitutable everywhere a CartItem is
    // expected, but wraps another CartItem to layer one stackable add-on charge on top.
    static abstract class CartItemDecorator extends CartItem {
        protected final CartItem wrapped;

        CartItemDecorator(CartItem wrapped) {
            super(wrapped.getProduct(), wrapped.getQuantity());
            this.wrapped = wrapped;
        }

        @Override
        abstract double getPrice(); // delegates to wrapped.getPrice() + adds its own charge
    }

    static class GiftWrapDecorator extends CartItemDecorator {
        private static final double FEE = 2.99;
        GiftWrapDecorator(CartItem wrapped) { super(wrapped); }
        @Override double getPrice() { return wrapped.getPrice() + FEE; }
    }

    static class EngravingDecorator extends CartItemDecorator {
        private static final double FEE = 5.00;
        EngravingDecorator(CartItem wrapped) { super(wrapped); }
        @Override double getPrice() { return wrapped.getPrice() + FEE; }
    }

    // ---------- Cart ----------
    static class Cart {
        private final List<CartItem> items = new ArrayList<>();

        void addItem(CartItem item) { items.add(item); }

        void removeItem(String productId) {
            items.removeIf(i -> i.getProduct().id.equals(productId));
        }

        double subtotal() {
            double total = 0;
            for (CartItem i : items) total += i.getPrice();
            return total;
        }

        int quantityFor(String productId) {
            int qty = 0;
            for (CartItem i : items) if (i.getProduct().id.equals(productId)) qty += i.getQuantity();
            return qty;
        }

        List<CartItem> getItems() { return items; }
    }

    // ---------- Pricing pipeline (Strategy) ----------
    interface PricingStep {
        double apply(double runningTotal, Cart cart);
    }

    static class TaxPricingStep implements PricingStep {
        private final double rate;
        TaxPricingStep(double rate) { this.rate = rate; }
        @Override public double apply(double runningTotal, Cart cart) { return runningTotal + runningTotal * rate; }
    }

    static class CouponDiscountPricingStep implements PricingStep {
        private final String couponCode;
        private final Map<String, Double> validCoupons;
        CouponDiscountPricingStep(String couponCode, Map<String, Double> validCoupons) {
            this.couponCode = couponCode; this.validCoupons = validCoupons;
        }
        @Override public double apply(double runningTotal, Cart cart) {
            if (couponCode == null || !validCoupons.containsKey(couponCode)) return runningTotal;
            double discount = validCoupons.get(couponCode);
            return runningTotal * (1 - discount);
        }
    }

    // ---------- Order lifecycle (State) ----------
    enum OrderStatus { PENDING_PAYMENT, PAID, SHIPPED, DELIVERED, CANCELLED }

    interface OrderState {
        OrderState onPaid(Order order);
        OrderState onShipped(Order order);
        OrderState onDelivered(Order order);
        OrderState onCancelled(Order order);
    }

    static class PendingPaymentState implements OrderState {
        @Override public OrderState onPaid(Order order) { order.status = OrderStatus.PAID; return new PaidState(); }
        @Override public OrderState onShipped(Order order) { throw new IllegalStateException("Cannot ship before payment"); }
        @Override public OrderState onDelivered(Order order) { throw new IllegalStateException("Cannot deliver before payment"); }
        @Override public OrderState onCancelled(Order order) { order.status = OrderStatus.CANCELLED; return new CancelledState(); }
    }

    static class PaidState implements OrderState {
        @Override public OrderState onPaid(Order order) { return this; }
        @Override public OrderState onShipped(Order order) { order.status = OrderStatus.SHIPPED; return new ShippedState(); }
        @Override public OrderState onDelivered(Order order) { throw new IllegalStateException("Cannot deliver before shipping"); }
        @Override public OrderState onCancelled(Order order) { order.status = OrderStatus.CANCELLED; return new CancelledState(); } // refund path
    }

    static class ShippedState implements OrderState {
        @Override public OrderState onPaid(Order order) { return this; }
        @Override public OrderState onShipped(Order order) { return this; }
        @Override public OrderState onDelivered(Order order) { order.status = OrderStatus.DELIVERED; return new DeliveredState(); }
        @Override public OrderState onCancelled(Order order) { throw new IllegalStateException("Cannot cancel a shipped order"); }
    }

    static class DeliveredState implements OrderState {
        @Override public OrderState onPaid(Order order) { return this; }
        @Override public OrderState onShipped(Order order) { return this; }
        @Override public OrderState onDelivered(Order order) { return this; }
        @Override public OrderState onCancelled(Order order) { throw new IllegalStateException("Cannot cancel a delivered order"); }
    }

    static class CancelledState implements OrderState {
        @Override public OrderState onPaid(Order order) { throw new IllegalStateException("Order is cancelled"); }
        @Override public OrderState onShipped(Order order) { throw new IllegalStateException("Order is cancelled"); }
        @Override public OrderState onDelivered(Order order) { throw new IllegalStateException("Order is cancelled"); }
        @Override public OrderState onCancelled(Order order) { return this; }
    }

    // ---------- Order (immutable snapshot + lifecycle) ----------
    static class Order {
        final String id;
        final List<CartItem> lineItems; // frozen at checkout time
        final double totalPrice;
        OrderStatus status;
        private OrderState state;

        Order(String id, List<CartItem> lineItems, double totalPrice) {
            this.id = id;
            this.lineItems = Collections.unmodifiableList(new ArrayList<>(lineItems));
            this.totalPrice = totalPrice;
            this.status = OrderStatus.PENDING_PAYMENT;
            this.state = new PendingPaymentState();
        }

        Order transitionTo(OrderStatus target) {
            switch (target) {
                case PAID: state = state.onPaid(this); break;
                case SHIPPED: state = state.onShipped(this); break;
                case DELIVERED: state = state.onDelivered(this); break;
                case CANCELLED: state = state.onCancelled(this); break;
                default: throw new IllegalArgumentException("Unsupported transition: " + target);
            }
            return this;
        }
    }

    static class PaymentResult {
        final boolean success;
        PaymentResult(boolean success) { this.success = success; }
    }

    // ---------- CheckoutService (Facade) ----------
    static class CheckoutService {
        private final List<PricingStep> pricingPipeline;
        private final Map<String, Order> ordersById = new HashMap<>();
        private final Map<String, Order> processedIdempotencyKeys = new HashMap<>();
        private int nextOrderId = 1;

        CheckoutService(List<PricingStep> pricingPipeline) {
            this.pricingPipeline = pricingPipeline;
        }

        Order checkout(Cart cart, String couponCode) {
            List<String> orderedProductIds = new ArrayList<>();
            for (CartItem item : cart.getItems()) {
                if (!orderedProductIds.contains(item.getProduct().id)) orderedProductIds.add(item.getProduct().id);
            }
            Collections.sort(orderedProductIds); // canonical order avoids cross-cart deadlock

            List<Product> reserved = new ArrayList<>();
            List<Integer> reservedQty = new ArrayList<>();
            try {
                for (String productId : orderedProductIds) {
                    Product product = productFor(cart, productId);
                    int qty = cart.quantityFor(productId);
                    product.decrementStock(qty); // throws OutOfStockException on failure
                    reserved.add(product);
                    reservedQty.add(qty);
                }
            } catch (OutOfStockException e) {
                for (int i = 0; i < reserved.size(); i++) reserved.get(i).restoreStock(reservedQty.get(i));
                throw e;
            }

            double total = cart.subtotal(); // includes decorator-priced add-ons
            for (PricingStep step : pricingPipeline) total = step.apply(total, cart);
            if (couponCode != null) {
                // coupon step is applied like any other pipeline step if wired in; here we allow ad-hoc override
            }

            Order order = new Order("ORD-" + (nextOrderId++), cart.getItems(), total);
            ordersById.put(order.id, order);
            return order;
        }

        Order confirmPayment(String orderId, PaymentResult result, String idempotencyKey) {
            if (processedIdempotencyKeys.containsKey(idempotencyKey)) {
                return processedIdempotencyKeys.get(idempotencyKey); // already processed: return same result, no double effect
            }
            Order order = ordersById.get(orderId);
            if (order == null) throw new OrderNotFoundException("No such order: " + orderId);

            if (result.success) {
                order.transitionTo(OrderStatus.PAID);
            } else {
                order.transitionTo(OrderStatus.CANCELLED);
                restoreInventory(order);
            }
            processedIdempotencyKeys.put(idempotencyKey, order);
            return order;
        }

        private void restoreInventory(Order order) {
            for (CartItem item : order.lineItems) item.getProduct().restoreStock(item.getQuantity());
        }

        private Product productFor(Cart cart, String productId) {
            for (CartItem item : cart.getItems()) if (item.getProduct().id.equals(productId)) return item.getProduct();
            throw new IllegalStateException("Product not in cart: " + productId);
        }
    }

    // ---------- Demo ----------
    public static void main(String[] args) {
        Product laptop = new Product("P1", "Laptop", 1000.0, 5);
        Product mug = new Product("P2", "Mug", 15.0, 10);

        Cart cart = new Cart();
        cart.addItem(new GiftWrapDecorator(new CartItem(laptop, 1))); // laptop + gift wrap
        cart.addItem(new EngravingDecorator(new CartItem(mug, 2)));   // 2 mugs + engraving

        System.out.println("Subtotal (with add-ons): " + cart.subtotal());

        Map<String, Double> coupons = new HashMap<>();
        coupons.put("SAVE10", 0.10);

        List<PricingStep> pipeline = new ArrayList<>();
        pipeline.add(new CouponDiscountPricingStep("SAVE10", coupons));
        pipeline.add(new TaxPricingStep(0.08));

        CheckoutService checkoutService = new CheckoutService(pipeline);
        Order order = checkoutService.checkout(cart, "SAVE10");
        System.out.println("Order created: " + order.id + " total=" + order.totalPrice + " status=" + order.status);
        System.out.println("Laptop stock after checkout: " + laptop.stock);

        Order confirmed = checkoutService.confirmPayment(order.id, new PaymentResult(true), "idem-key-1");
        System.out.println("After payment: " + confirmed.status);

        // Retried webhook with same idempotency key must not double-process
        Order retried = checkoutService.confirmPayment(order.id, new PaymentResult(true), "idem-key-1");
        System.out.println("Retry same order id? " + (retried == confirmed));

        confirmed.transitionTo(OrderStatus.SHIPPED);
        confirmed.transitionTo(OrderStatus.DELIVERED);
        System.out.println("Final status: " + confirmed.status);
    }
}

class CheckoutService {
    vector<shared_ptr<PricingStep>> pricingPipeline;
    map<string, shared_ptr<Order>> ordersById;
    map<string, shared_ptr<Order>> processedIdempotencyKeys;
    int nextOrderId = 1;
public:
    CheckoutService(vector<shared_ptr<PricingStep>> pipeline) : pricingPipeline(move(pipeline)) {}

    shared_ptr<Order> checkout(Cart& cart, const string& couponCode) {
        vector<string> orderedProductIds;
        for (auto& item : cart.getItems()) {
            if (find(orderedProductIds.begin(), orderedProductIds.end(), item->getProduct()->id) == orderedProductIds.end())
                orderedProductIds.push_back(item->getProduct()->id);
        }
        sort(orderedProductIds.begin(), orderedProductIds.end()); // canonical order avoids cross-cart deadlock

        vector<Product*> reserved;
        vector<int> reservedQty;
        try {
            for (auto& productId : orderedProductIds) {
                Product* product = productFor(cart, productId);
                int qty = cart.quantityFor(productId);
                product->decrementStock(qty); // throws OutOfStockException on failure
                reserved.push_back(product);
                reservedQty.push_back(qty);
            }
        } catch (OutOfStockException&) {
            for (size_t i = 0; i < reserved.size(); i++) reserved[i]->restoreStock(reservedQty[i]);
            throw;
        }

        double total = cart.subtotal(); // includes decorator-priced add-ons
        for (auto& step : pricingPipeline) total = step->apply(total, cart);

        auto order = make_shared<Order>("ORD-" + to_string(nextOrderId++), cart.getItems(), total);
        ordersById[order->id] = order;
        return order;
    }

    shared_ptr<Order> confirmPayment(const string& orderId, PaymentResult result, const string& idempotencyKey) {
        auto found = processedIdempotencyKeys.find(idempotencyKey);
        if (found != processedIdempotencyKeys.end()) return found->second;

        auto it = ordersById.find(orderId);
        if (it == ordersById.end()) throw OrderNotFoundException("No such order: " + orderId);
        auto order = it->second;

        if (result.success) {
            order->transitionTo(OrderStatus::PAID);
        } else {
            order->transitionTo(OrderStatus::CANCELLED);
            restoreInventory(*order);
        }
        processedIdempotencyKeys[idempotencyKey] = order;
        return order;
    }

private:
    void restoreInventory(Order& order) {
        for (auto& item : order.lineItems) item->getProduct()->restoreStock(item->getQuantity());
    }

    Product* productFor(Cart& cart, const string& productId) {
        for (auto& item : cart.getItems()) if (item->getProduct()->id == productId) return item->getProduct();
        throw runtime_error("Product not in cart: " + productId);
    }
};
